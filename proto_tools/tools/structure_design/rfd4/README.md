# RFD4-Proteina

> [!NOTE]
> **License:** RFD4-Proteina is open source and free for academic and commercial use under a BSD-3-Clause license. Please refer to [the license](https://github.com/RosettaCommons/RFD4-Proteina/blob/main/LICENSE) for full terms.

## Overview

[RFD4-Proteina](https://github.com/RosettaCommons/RFD4-Proteina) is a flow-matching generative model, built jointly by the [Institute for Protein Design](https://www.ipd.uw.edu/) and [NVIDIA](https://www.nvidia.com/), that co-generates protein sequence and all-atom structure in a single pass. Given a starting structure and a set of conditions — motifs, hotspots, ligands, burial, fold class — it returns designs that already carry their sequences, so no separate inverse-folding step is needed. The same checkpoint also runs inverse folding on a fixed backbone.

## Background

RFD4-Proteina ([Corley et al., 2026](https://rfd4-proteina.org/assets/paper/RFD4-Proteina.pdf)) generates biomolecular structure and sequence together by integrating a learned flow from noise to data, in the manner of a [diffusion model](https://en.wikipedia.org/wiki/Diffusion_model) but with the straighter probability paths of flow matching. Its defining architectural choice is a *partially latent* representation inherited from NVIDIA's Proteina-Complexa and La-Proteina line of work: explicit coordinates are carried for a single anchor atom per polymer token — the α-carbon of an amino acid — while sidechain geometry and residue identity ride along as per-residue latents that a paired autoencoder decodes into all-atom coordinates and an amino-acid sequence. Atomized components such as ligands are the exception and keep their explicit atom identities and connectivity. That is why RFD4-Proteina is a sibling of, not a fork of, [RFdiffusion3](https://bio-pro.mintlify.app/tools/structure-design/rfdiffusion3) ([Butcher et al., 2025](https://doi.org/10.1101/2025.09.18.676967)): the two share a design-problem formulation and a conditioning vocabulary, but not a generative backbone. The released bundle is roughly 435.6M parameters across the denoising trunk and its matching autoencoder, which always load as a pair.

Four changes separate RFD4-Proteina from its predecessor. The training corpus is expanded well beyond the [Protein Data Bank](https://www.rcsb.org/) with physically simulated structures and structure-prediction distillation spanning small molecules, nucleic acids, cyclic peptides, and interfaces. The architecture strengthens the pair representation: triangle multiplicative updates run in every other transformer block, single-to-pair communication is richer, and the hidden dimension is wider. "Intrinsic reasoning" moves trunk recycling inside the generative loop — the trunk recycles at *every* integration timestep rather than once as an upstream feature stage — so the model spends more compute refining its own intermediate hypotheses. "Extrinsic reasoning" adds search over whole trajectories, keeping the branches that score well. Together these raise in-silico success on the hardest conditioning regimes: against RFdiffusion3, the preprint reports a 14.3% versus 2.4% clustered pass rate on small-molecule binding, and 3.5% versus 0.5% on DNA binding relative to fixed-DNA RFdiffusion3. Protein-binder performance is measured on the union of the Proteina-Complexa and RFdiffusion3 benchmarks, 24 targets in total.

The practical consequence for a designer is that sequence is no longer a second stage. RFdiffusion3 co-designs a sequence alongside its backbone, but published benchmarks typically redesign those backbones with a message-passing inverse-folding pass such as [LigandMPNN](https://bio-pro.mintlify.app/tools/inverse-folding/ligandmpnn) before evaluating them; RFD4-Proteina emits a packed all-atom structure and its sequence at once, and can also be pointed at an existing backbone to do inverse folding directly. Upstream's [conditioning status table](https://github.com/RosettaCommons/RFD4-Proteina/blob/main/docs/reference/annotations.md) lists a broad surface as supported — indexed and unindexed coordinate motifs, sequence constraints, hotspot residues, partial diffusion, inverse folding, small molecules and other ligands, internal coordinates, hydrogen-bond donor/acceptor/both roles, relative-accessible-surface-area burial, secondary structure, [CATH](https://www.cathdb.info/) C.A.T fold class, per-identity sequence probabilities, π-stacking, and π-cation interactions. Symmetry is the one conspicuous omission and is the table's only *Planned* row.

## Tools

### RFD4-Proteina Design (`rfd4-design`)

Generates novel all-atom structures together with their amino-acid sequences, subject to the conditions on each `RFD4DesignSpec`. One spec is one design task; each produces `num_replicates` designs, returned as an `RFD4Designs` bundle that keeps the output aligned 1:1 with the input specs.

#### Applications

Reach for this whenever the deliverable is a new backbone *and* a sequence under spatial constraints: de novo protein binders against a target hotspot, motif scaffolding around a catalytic or epitope motif (indexed when the motif's pose should be preserved, unindexed when only its internal geometry matters), enzyme and active-site design around a small-molecule or nucleic-acid pocket, fold-class- or burial-steered monomer generation, and partial-diffusion refinement of a design you already have. Because sequence comes out of the same pass, the natural next step is validation rather than inverse folding — refold the design and compare it back to the generated backbone.

#### Usage Tips

- **Pass either a PDB or an mmCIF; the wrapper converts.** Upstream accepts mmCIF only — [its FAQ](https://github.com/RosettaCommons/RFD4-Proteina/blob/main/docs/how-to/faq.md) explains that PDB does not reliably encode the bonds and formal charges the model consumes, so `.pdb` is rejected outright. On the default path this wrapper writes an RFD4-readable CIF from either format and pins `label_asym_id` to the author chain id, so `sel('A')` means chain A whichever format you started from. That preparation is skipped when `input_as_annotated_cif=True`: such an input reaches RFD4 byte for byte, deliberately, so the `condition_*` columns it carries survive — no chain-id pinning and no renumbering happen.
- **Residue ids are read in author numbering by default, and `residue_numbering` is the switch.** RFD4 resolves every `contig` and condition residue id against the mmCIF [`label_seq_id`](https://github.com/RosettaCommons/RFD4-Proteina/blob/main/docs/reference/yaml-json.md), not the `auth_seq_id` a PDB displays. The default `residue_numbering="auth"` lets you write the numbering you see in your input, and the wrapper translates it through the per-chain author→label map it builds while preparing the CIF — which holds whichever numbering that CIF ends up carrying. A PDB input has no `label_seq_id` at all, so preparation assigns it a fresh 1-based per-chain counter; a CIF input keeps whatever `label_seq_id` it already carries, which need not start at 1 — upstream's own `pdl1_target_5o45_cropped.cif` is numbered 17-131 going in and 17-131 coming out. So with `residue_numbering="label"`, and with any `input_as_annotated_cif=True` input (which is passed through untranslated), write the ids the file actually carries. Ids inside `raw_conditions` are never translated either.
- **The `contig` token forms match RFdiffusion3's, but the semantics do not.** Tokens are comma-separated, and `/0` (chain break), `A42-48` (preserved input segment) and `20-30` (expandable segment) are written exactly as for [`rfdiffusion3-design`](https://bio-pro.mintlify.app/tools/structure-design/rfdiffusion3). How they resolve is what differs: RFD4 reads residue ids against `label_seq_id` rather than author numbering, and it requires at least one preserved segment because there is no `length` field to size a design on its own. It also carries forms beyond that shared core: `E1:2-20` is a *named* expandable segment whose name becomes its `res_name` so conditions can select it, `A52` (or `AA52` for a multi-letter chain id) preserves a single residue, and a trailing `P` / `R` / `D` suffix sets a segment's chain type. The suffix applies to named and unnamed expandable segments alike, so `10R` is a ten-residue RNA segment rather than ten repeats; it defaults to the run's anchor chain type and is rejected when it disagrees with that anchor. The spec dialect that used to surround the contig is gone: `length`, `symmetry`, `unindex` and `select_*` are all rejected. RFdiffusion1's slash-separated contigs are a genuinely unrelated grammar. Chain letters are assigned per run between `/0` breaks rather than left to right, and omitting `contig` entirely keeps the whole input.
- **Conditions are coupled, not independent.** Fixing a sidechain coordinate also forces sequence conditioning on that residue, and atomized tokens (ligands, PTMs, non-canonical residues) are always sequence-conditioned. Overlapping entries *within* one condition resolve last-write-wins, so the order of a single condition's selections matters. Separately, absolute and internal coordinates are mutually exclusive on an atom: an atom that already carries absolute conditioning has to be released by `free_coordinates` before a `rigid_groups` entry can claim it. Ligands and modified residues must carry Kekulized bonds (`AROMATIC_SINGLE` / `AROMATIC_DOUBLE`, never `AROMATIC`) for their bond orders to reach the model.
- **`recycle_strategy` is the main compute-for-quality dial, and it pins `nsteps`.** The `midpeak` schedules total 120 / 150 / 180 trunk passes at `low` / `medium` / `high`; the `flat` and `front_loaded` schedules total 120 / 180 / 300. The `thinking_low` / `thinking_medium` / `thinking_high` aliases are the front-loaded schedules, and the default `recycle_strategy="thinking_medium"` is `medium/front_loaded`, 180 trunk passes. All three `low/*` presets cost the same 120 passes and differ only in how they spend them, so `low/flat` is not cheaper than the others — it just distributes the budget evenly. Every preset expands to exactly 60 integration steps and upstream requires the two to agree, so `nsteps` must stay at 60 while a preset is set — the config rejects any other combination before dispatch rather than letting upstream fail after loading the model. Setting `recycle_strategy=None` disables recycling and is the only way to run a custom `nsteps`.
- **Only the presets are in distribution: do not shorten a de novo run.** A design run at `recycle_strategy=None, nsteps=20` executes fine but collapses to poly-alanine. Every released schedule runs 60 integration steps at a recycling depth of at least 1, so that setting perturbs two things at once — the recycle depth and the step count — and lands far outside anything the model was ever sampled at. Reduced-step settings are useful for smoke-testing the plumbing (which is what `RFD4DesignConfig.minimal()` does) and for nothing else; any `low/*` preset is the cheapest result you can still trust.
- **The two partial-diffusion interfaces have inverted senses.** `partial_trajectory_fraction_steps` runs only the final fraction of the trajectory, so a *low* value such as `0.3` stays close to the input. `partial_t_backbone` and `partial_t_latent` are starting corruption levels, so a *high* value near 1 stays close to the input and a low value approaches full generation. The two interfaces are mutually exclusive, and partial diffusion normally wants `input_as_annotated_cif=True` on a previous RFD4 output so the conditioning survives the round trip.
- **`sequence_probabilities` is how you forbid an identity outright.** An entry with `probability=0.0` on `CYS` requests a cysteine-free design; omitted identities stay flexible and share the remaining probability mass. Values set on one residue may not sum above 1.

### RFD4-Proteina Inverse Folding (`rfd4-inverse-folding`)

Designs a sequence and sidechains for a fixed input backbone, returning each replicate as an independent sequence for the same fold together with its packed all-atom coordinates.

#### Applications

Use this to generate a diverse sequence set for a backbone that already exists — one you designed with `rfd4-design` or `rfdiffusion3-design`, a native scaffold you want to redesign, or a predicted fold you want to stabilise — and to do it with all-atom context rather than backbone geometry alone. Because the packed sidechains come back with the sequence, it doubles as a sidechain-packing step, and it slots in as an alternative to `proteinmpnn-sample`, `ligandmpnn-sample`, and `fampnn-sample` when the backbone's ligand and sidechain environment matters.

#### Usage Tips

- **Lower `sequence_sampling.tsr_k` to raise sequence diversity.** `tsr_k` is a temporal score-rescaling sharpness, so higher `k` is a *lower* sampling temperature; the upstream default for the sequence/sidechain latent modality is `4.0`. Dropping it toward `2.0` produces a more varied set of sequences for the same fold, at some cost in per-sequence quality.
- **Conditions on the input spec still apply.** A run can reveal part of the sequence with `known_sequence`, steer solvent exposure with `burial`, or exclude an identity with a `sequence_probabilities` entry, exactly as in design. What is *not* exposed here are the design-time controls — `guidance_w` and the partial-diffusion settings live on `rfd4-design` only.
- **Give it a complete all-atom backbone.** Inverse folding holds the input structure on resampled forward marginals, so a cropped or partially resolved structure has nothing coherent to hold. Fed PDB 5O45 cropped to PD-L1 residues 17-131 — a binder *target* carrying 15 NaN-coordinate atoms across 6 unresolved sidechains — it returns a CA-only poly-alanine trace rather than a design. Upstream's own CLI returns the identical result on that file, so this is a property of the model and the input, not of this wrapper: check that your backbone is complete before reading anything into a degenerate sequence.

## Toolkit Notes

These apply to every RFD4-Proteina tool in this toolkit (`rfd4-design`, `rfd4-inverse-folding`).

- **Symmetric oligomer design is not available.** Upstream lists symmetry as *Planned*, and it is the one capability RFD4-Proteina gives up relative to RFdiffusion3. Use [`rfdiffusion3-design`](https://bio-pro.mintlify.app/tools/structure-design/rfdiffusion3) for cyclic and dihedral symmetry.
- **A GPU is required, not merely recommended.** The `rfd4-generate` console script this toolkit invokes (upstream's `rfproteina/generate.py`) constructs its Lightning trainer with `accelerator="gpu"` unconditionally, so `device="cpu"` does not run slowly — it hides the GPUs and trips a Lightning misconfiguration error. Environment setup is gated to match, at three separate points: `setup.sh` refuses any host that is not Linux x86_64, refuses a non-CUDA host outright because there is no CPU path to fall back to, and refuses a CUDA host whose NVIDIA driver major version is below 525.
- **Weights are ungated and downloaded automatically.** `model_checkpoint` defaults to the `nvidia/RFD4-Proteina` HuggingFace repo, pinned by `model_revision` for reproducible loads, and needs no access request or token. The denoising trunk and its matching autoencoder always load together, so `model_checkpoint` must name a bundle that contains both. `adapter_path` is a different kind of artifact: a PEFT/LoRA adapter directory (8.3 MB of LoRA tensors upstream) that must have been fine-tuned against exactly the base-plus-autoencoder pair `model_checkpoint` resolves to.
- **GPU memory scales with `batch_size` and design length.** Confirm the longest input in a run fits at `batch_size=1` before raising it, and reduce `batch_size` first when memory is exhausted.
- **`use_torch_compile` is off by default on purpose.** Enabling it compiles the trunk across the 15 upstream length buckets (128 through 1024 residues), so the first call pays a long compile that only amortises over large runs.
- **Designs carry no confidence score.** Validate by refolding the designed sequence with a structure predictor — [`boltz2-prediction`](https://bio-pro.mintlify.app/tools/structure-prediction/boltz2) or [`esmfold-prediction`](https://bio-pro.mintlify.app/tools/structure-prediction/esmfold) — and comparing the predicted backbone against the generated one. Each `RFD4Design` exposes a predictor-ready `complex` for exactly this; read its sequences with `extract_protein_chains()` or `chain_sequence_map()`, since a ligand, DNA, or RNA design holds `Fragment` entries that carry a SMILES or CCD code rather than a `sequence`.
- **Output is grouped per input spec.** `designed_structures` holds one `RFD4Designs` bundle per spec in input order, each holding `num_replicates` designs, so `output[i]` is the i-th bundle and individual designs are reached by iterating a bundle. A spec that produced nothing yields an empty bundle rather than shifting later ones.
- **Sampling is stochastic, and `seed` is honoured.** Two seeded runs of `rfd4-inverse-folding` on the same backbone reproduced byte-identical sequences and structures in our testing, so a pinned seed is a usable handle on a result. Bit-exactness is still not guaranteed in general — floating-point reduction order on the GPU can vary — so treat a reproduced run as likely rather than certain, and set `deterministic_sampling=True` to integrate both modalities as an ODE if you need to remove mid-trajectory noise injection as well. Either way, generate and rank a batch rather than trusting a single sample.
- **Several upstream features are deliberately out of scope here.** Reward-guided beam search is unexposed for two separate reasons: its oracle-scored configs need a containerized AlphaFold2 or AlphaFold3/OpenFold3 refolding runtime that this toolkit does not provision (AF3/OF3 via Apptainer; AF2 also via Docker or Pyxis, selected by `AF2_RUNTIME_BACKEND`), and its structure-only configs, such as `inference_experiment=sm_binder_hbond_search`, need a `search` block surface that is not exposed either. Inline *tagged* metrics are hardcoded off (`metrics_tags=[]`) for the oracle reason alone; see the next note for what that does and does not switch off. Also unexposed: the upstream `rfd4-evaluate` entry point, antibody and VHH design (upstream supports it only through a bundled example config and otherwise trips a residue-numbering safeguard), and the Diffusers pipeline, which is merged upstream ([huggingface/diffusers#15088](https://github.com/huggingface/diffusers/pull/15088)) but not yet in a tagged release, so it would need Diffusers from git plus the separate [`nvidia/RFD4-Proteina-Diffusers`](https://huggingface.co/nvidia/RFD4-Proteina-Diffusers) weights repo. Note that there is no separate folding mode to expose: upstream ships two generation presets, `inference_base` and `inverse_folding` (`folding_only` is a *training* design-task preset), and at inference folding is simply `C_SEQ` sequence conditioning, which `known_sequence` already covers.
- **No refolding oracle is ever invoked, but a little untagged metadata still is.** `metrics_tags=[]` switches off every *tagged* metric, which is the whole oracle-scored set, so no AlphaFold2, AlphaFold3, or OpenFold3 refolding ever runs here. It does not switch off untagged metrics: upstream's `unknown_residue_filter` carries no tag and still runs, so each design arrives with a small amount of untagged composition metadata in its `metadata`. The wrapper also passes `delete_failing_pre_oracle=False` so that upstream cannot act on that filter — a design that trips it is returned to you rather than deleted from the output directory while the run still exits 0, so a design is never silently discarded.
- **Optional refolding oracles distributed alongside RFD4-Proteina carry their own terms.** Upstream distributes runtime *container images* for AlphaFold2 and AlphaFold3/OpenFold3 — third-party code under its own licenses, some of which restrict commercial use or redistribution — plus Apache-2.0 ported OpenFold3 weights. It does not distribute the AlphaFold2 parameters or the AlphaFold3 weights; those come from DeepMind under DeepMind's terms. None of this gates this toolkit, which never invokes an oracle, but it would apply if you stood one up yourself.
